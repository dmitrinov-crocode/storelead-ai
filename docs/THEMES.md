# Справочник тем: что в нём есть и как его обновлять

Файл: `src/analysis/themeCatalog.json`. Его читает анализатор темы (`src/analysis/theme.ts`,
задача 2-21), чтобы сказать, насколько магазин отстал от актуальной версии своей темы.

## Что откуда берётся

В справочнике два вида фактов, и стареют они по-разному.

**Архитектура** (`vintage` / `os2` / `theme_blocks`) не устаревает. Debut была темой до Online
Store 2.0 в момент выпуска и другой уже не станет, поэтому классификация по имени безопасна
бессрочно. Она проставлена вручную и у каждой записи есть поле `source` с обоснованием.

**Версии** устаревают в момент выхода релиза. Их несут только темы с публичным проверяемым
источником. Публичных репозиториев тем ровно два — проверено обращением к GitHub API 2026-09-01,
все остальные имена бесплатных тем Shopify отвечают 404:

| Тема    | Репозиторий       | Что отдаёт                                                  |
| ------- | ----------------- | ----------------------------------------------------------- |
| Dawn    | `Shopify/dawn`    | GitHub releases — полная история версий с датами            |
| Horizon | `Shopify/horizon` | релизов и тегов нет; версия в `config/settings_schema.json` |

Разница принципиальна для анализа:

- с историей считается **и** отставание в релизах, **и** возраст версии, на которой сидит магазин;
- без истории известна только самая новая версия. Тогда единственное, что можно утверждать, —
  «магазин не на последней версии», и вердикт не опускается ниже `slightly_outdated`. Насколько
  именно он отстал и как давно — неизвестно, и придумывать это нельзя.

Платные темы (Prestige, Impulse, Motion, Pipeline и прочие) не публикуют ничего машиночитаемого.
Их в справочнике нет: тема, которой нет в файле, честно даёт `null`, а не догадку.

## Обновление

```bash
npm run pipeline -- themes update          # обновить файл
npm run pipeline -- themes update --check  # только показать расхождения, выход 1 если есть
```

Команда обходит записи с полем `github`, тянет релизы, а при их отсутствии — `theme_version` из
`config/settings_schema.json` ветки `main`. Остальные записи не трогает.

Ограничение GitHub без токена — 60 запросов в час, при двух темах этого хватает с запасом. Если
упирается, передайте токен: `--token <t>` или переменной `GITHUB_TOKEN`.

**Ошибка загрузки не стирает данные.** Запись, которую не удалось обновить, остаётся как была, а
команда пишет `FAILED` и завершается с кодом 1. Устаревшая версия лучше пустой: иначе одна плохая
минута у GitHub обнулила бы вердикты по всем магазинам на Dawn.

Поле `updatedAt` в файле — дата последней **проверки**, а не последнего изменения.

После обновления справочника вердикты пересчитываются сами: шаг `theme_apps` намеренно не имеет
`isSatisfied` и на каждом прогоне судит заново.

## Как добавить тему вручную

```json
"prestige": {
  "displayName": "Prestige",
  "source": "чем подтверждается — ссылка или описание проверки",
  "releases": []
}
```

Ключ — имя в нижнем регистре, поиск идёт по нему (StoreLeads присылает и `Dawn`, и `dawn`).
Поле `source` обязательно: справочник существует ровно для того, чтобы утверждения о теме можно
было проверить.

Архитектуру платной темы ставить по имени нельзя — она зависит от версии: магазин может сидеть на
пре-OS 2.0 сборке темы, которая сегодня продаётся как OS 2.0. Если версионного порога вы не знаете,
`architecture` лучше не указывать вовсе: пустое поле означает «не знаем», а неверное значение
попадёт в письмо клиенту как факт.
