### Решения, принятые при реализации

| Решение                                         | Причина                                                                                                                                                                 |
| ----------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `node:sqlite` вместо `better-sqlite3` + Drizzle | Встроен в Node 22+, нет нативной сборки (на Node 25 `better-sqlite3` собирался бы из исходников). API совместим с `better-sqlite3`, замена при необходимости тривиальна |
| Миграции обычным SQL, без ORM                   | Схема из 15 таблиц читается целиком в одном файле; репозитории дают типы там, где они нужны                                                                             |

| Путь к БД задаётся только в `src/config`        | `next.config.ts` импортирует core-конфиг и прокидывает путь в дашборд через `env` — единственный источник истины                                                        |
| `await connection()` перед SQL в дашборде       | Next 16 иначе выполняет синхронные запросы `node:sqlite` на пререндере и запекает данные времени сборки                                                                 |

### Решения по 2.1–2.2 (реализовано)

| Решение                                                                                                       | Почему                                                                                                                                        |
| ------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Горизонтальный скролл меряется по `documentElement.clientWidth`, а не `window.innerWidth`                     | На мобильной эмуляции браузер расширяет layout viewport под контент, `innerWidth` растёт вместе с переполнением — проверка не срабатывала бы  |
| Добавление в корзину подтверждается через `/cart.js`, а не по DOM                                             | Тема может показать «добавлено» и ничего не отправить. Нет `/cart.js` (не Shopify) → issue не создаётся: нет доказательства — нет утверждения |
| Поле промокода в корзине и способы оплаты на checkout собираются как факты, но **не** становятся issue        | Shopify показывает их на следующих шагах, куда мы намеренно не заходим. Иначе false positive почти на каждом магазине                         |
| Заказ не оформляется никогда: checkout проверяется на первом шаге, пока корзина жива, затем корзина очищается | Требование 2-14. Checkout-URL привязан к корзине, поэтому проверка идёт хуком внутри cart-флоу                                                |
| Консольные строки `Failed to load resource` игнорируются                                                      | Chromium дублирует ими каждый упавший запрос, который уже записан в `httpErrors`/`failedRequests` с URL, статусом и типом ресурса             |
| Статусы 401/403/405/429/999 и 5xx на внешних ссылках не считаются битой ссылкой                               | Это ответ анти-бота или чужой сервер, а не дефект магазина                                                                                    |
| In-page код (`page.evaluate`) написан без вложенных функций                                                   | `tsx` компилирует их с esbuild-хелпером `__name`, которого нет в браузере — падало на runtime, а не на сборке                                 |
| Браузер в пуле мемоизируется по промису запуска, а не по результату                                           | Два параллельных магазина запускали два Chromium, осиротевший не давал процессу выйти                                                         |
| Регексы согласия/цен — юникодные (`\p{L}`, `\d\s*zł`)                                                         | `\w` не матчит «Akceptuję», `\b` не работает после `ł`; польские баннеры не закрывались бы вообще                                             |

Скриншоты: `screenshots/<домен>/audit-<id>/<page>-<viewport>.png`, размеры читаются из PNG-заголовка.
Шаг `audit` зарегистрирован в пайплайне, получил `teardown()` — иначе Chromium не давал CLI завершиться.

### Что выяснилось про PageSpeed Insights (2-19, проверено 2026-09-01)

| Находка                                                                                                                                                                                   | Следствие                                                                                                                                                                         |
| ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Без ключа API не работает вовсе.** Keyless-запрос отвечает 429 с `quota_limit_value: "0"` — проверено дважды, на двух разных URL                                                        | `PAGESPEED_API_KEY` стал обязательным для шага. Комментарии «works keyless at a lower quota» в `.env.example` и `src/config` исправлены — они были неверны                        |
| Lighthouse не умеет мерить INP: нужна реальная интерактивность                                                                                                                            | INP берётся только из поля (CrUX `loadingExperience`) и остаётся `null` для магазинов без трафика — а это большинство сегмента. `sources` в метриках говорит, откуда каждое число |
| PSI отвечает **200 OK** на страницу, которая не загрузилась: `lighthouseResult.runtimeError.code` = `ERRORED_DOCUMENT_REQUEST` / `DNS_FAILURE` / `NO_FCP`, категории при этом отсутствуют | Без проверки `runtimeError` в БД лёг бы performance = 0 у живого магазина. Метрики возвращают `runtimeError`, а не нули                                                           |
| Аудиты, которые Lighthouse не смог выполнить, приходят с `scoreDisplayMode: 'error'` и без `numericValue`                                                                                 | Чтение `numericValue` вслепую дало бы LCP = 0. Такие аудиты дают `null`                                                                                                           |
| `score: null` у категории означает «не посчитано», а не ноль                                                                                                                              | `null` сохраняется как `null`; настоящий `score: 0` пишется как 0                                                                                                                 |
| Квота исчерпана — это 429, но старые деплои PSI отвечают 403 с `reason: rateLimitExceeded`                                                                                                | Ретраить или нет решает `reason`, а не статус: 403 из-за неверного ключа не должен ретраиться весь прогон                                                                         |
| Неподнявшийся сайт возвращается как 400/500 с `Lighthouse returned error: <CODE>` в тексте                                                                                                | Код вынимается в `PagespeedError.lighthouseErrorCode`, ретрая нет: это факт о магазине, а не сбой запроса                                                                         |

Лаборатория против поля: лабораторные числа (`lighthouseResult`) есть всегда и меряются одинаково для
всех магазинов, поэтому они основные; поле (CrUX) подставляется только там, где лаборатории нет —
TTFB — и целиком владеет INP.

Фикстуры: `quota-exceeded.json` и `run-mobile.json` — **записанные живые ответы** (последний снят
2026-09-01 по keyshorts.com, Lighthouse 13.4.1, обрезан до потребляемых полей: полный ответ 1.1 МБ).
`run-failed.json` собран по схеме вручную — поймать живой `runtimeError` на заказ нельзя.

| Решение                                                                                         | Почему                                                                                                               |

### Требование к выходу Epic 4 (уточнено 2026-09-02)

Контакты магазина раскладываются по **трём колонкам**, а не по одному полю:

| Колонка     | Что попадает                                              | Откуда                                            |
| ----------- | --------------------------------------------------------- | ------------------------------------------------- |
| Email       | ящик, похожий на живого человека: `anna@`, `a.kowalska@`  | 4-02 + 4-03                                       |
| LinkedIn    | профиль человека, иначе страница компании                 | ссылки самого магазина (4-02), позже SERP из 4-07 |
| Общие ящики | `info@`, `support@`, `biuro@`, `zamowienia@`, `no-reply@` | 4-03                                              |

Причина разделения: для человека, разбирающего лид, это три разные вещи — кому писать, кого посмотреть, и куда писать, если персоны нет. `collectStoreContacts()` возвращает ровно эти три корзины; дашборд показывает по колонке на каждую (6-03/6-07).

### Решения по 4-05, 4-06, 4-07 (реализовано 2026-09-08)

Провайдер — **OpenAI `web_search`**. Сравнивались три:

| Провайдер             | За                                                                                              | Против                                                            |
| --------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Serper                | Сырой Google SERP, `site:` работает буквально. 2 500 бесплатных ≈ 800 магазинов                 | Бесплатные разовые, новый аккаунт и ключ                          |
| Exa                   | $10 в месяц без карты, `includeDomains` — фильтр параметром, а не строкой в запросе             | Нейропоиск, ранжирование менее предсказуемо; тоже новый провайдер |
| **OpenAI web_search** | Ключ уже в `.env`; ~$10 за 1000 вызовов → 300 запросов ≈ $3; **есть `filters.allowed_domains`** | Модель между нами и SERP — снимается grounding-фильтром (ниже)    |

Решающим оказалось то, что у `web_search` **тоже есть фильтр по доменам параметром**
(`filters.allowed_domains`) — единственное преимущество Exa над `site:`. Так что выбор свёлся к
«новый аккаунт против уже имеющегося ключа».

| Решение                                                                                                                  | Причина                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Интерфейс `WebSearchProvider` (`collectors/websearch/provider.ts`) — запрос, домены, `maxResults` → `hits[]`             | Наименьший общий знаменатель трёх провайдеров. 4-06 и 4-07 написаны против него, а не против OpenAI: смена провайдера стоит одного файла                                                                                                                                                                     |
| **Grounding-фильтр**: URL из ответа модели принимается, только если он есть в `action.sources` или в `url_citation`      | Модель, которую просят пересказать выдачу, может назвать правдоподобный URL, где не была. Выдуманный профиль в письме — худший отказ проекта. Отброшенные считаются и логируются. Это гард 3-05, применённый к другому типу выхода                                                                           |
| Заголовок берётся из `url_citation`, а не из ответа модели                                                               | Первый пришёл со страницы, второй перепечатан                                                                                                                                                                                                                                                                |
| `urlKey` схлопывает страновые поддомены **только для linkedin.com** (список хостов по имени)                             | Поиск отдаёт `pl.linkedin.com/in/anna`, цитата — `www.linkedin.com/in/anna`. При строгом сравнении весь польский сегмент отсеивался бы собственной же проверкой. Общее правило «резать любой двухбуквенный лейбл» схлопнуло бы и `de.`/`en.wikipedia.org` — это разные страницы. Нашлось тестом, не прогоном |
| Имя берётся **только из заголовка**, не из слага                                                                         | Слаг — это URL, а не утверждение, что кого-то так зовут                                                                                                                                                                                                                                                      |
| Хит без привязки к магазину **отбрасывается**, а не хранится с низким confidence                                         | Профиль, в котором ни заголовок, ни сниппет, ни слаг не упоминают магазин, — это другая Anna Kowalska. Три способа привязки: бренд в заголовке, бренд или домен в сниппете, бренд в слаге                                                                                                                    |
| Категорийное слово брендом не считается (`brand.ts`, `GENERIC_LABELS`)                                                   | `domainLabel('sklep.pl')` — это `sklep`, польское «магазин»: оно есть в заголовке у каждого продавца рынка, и привязка по нему сделала бы своим любой e-commerce-профиль в Польше. Полный хост (`skleppl`) и многословный бренд остаются рабочими                                                            |
| Разбор заголовка — детерминированный, `looksLikePersonName` и `detectRole` переиспользованы из 4-04                      | Стоп-лист, поймавший «Data Protection Office» на keyshorts.com, работает и здесь. Модель, которую спросили «кто основатель», ответила бы за каждый магазин, включая те, где основателя в LinkedIn нет                                                                                                        |
| Потолок confidence для найденного поиском — **0.50**, ниже любого источника с витрины                                    | Магазин, утверждающий «наш основатель — Анна», — это доказательство; поисковик, вернувший профиль с упоминанием магазина, — предположение                                                                                                                                                                    |
| Найденный человек с тем же именем **сливается в строку витрины**, а не добавляется второй                                | Поиск донёс ссылку на профиль, которой той строке не хватало, и титул, если About его не назвал. Ключ сравнения — `nameKey`, так что «Anna Kowalską» и «Anna Kowalska» — один человек                                                                                                                        |
| Поиск запускается, **только если витрина не назвала ни одного человека**, и останавливается на первом человеке с титулом | Это и есть правило расхода: скрап бесплатный, поиск — нет                                                                                                                                                                                                                                                    |
| Поиск идёт и тогда, когда витрина ответила **429**                                                                       | Это случай, ради которого он и нужен: 5 из 12 магазинов прогона 2026-09-02 отдали 429, и шаг отчитался «контактов нет». Поиск ходит в выдачу, а не к магазину, так что остывающему домену он ничего не стоит                                                                                                 |
| Бюджет на прогон (`WEB_SEARCH_MAX_SEARCHES_PER_RUN=100`) в форме `PagespeedQuota`                                        | `--force` по большому батчу — единственное, что превращает трёхдолларовую фичу в счёт                                                                                                                                                                                                                        |
| Третий шаблон 4-06 (открытый веб) собирается, но **не запускается**                                                      | 4-07 читает только LinkedIn-хиты; платить за результат, который никто не разбирает, незачем. Шаблон ждёт AI-половину 4-04                                                                                                                                                                                    |

| Вариация меняет **угол, а не тон**                                           | Правила 5-01 (не продаём, 80–150 слов, без лести) одинаковы всегда. Разное — с чего начать: у магазина со сломанной корзиной и у просто медленного это разные первые строки                                                |
| У каждой категории есть не только «с чего начать», но и **«чего не делать»** | Каждая категория провоцирует свою ошибку. `REDESIGN_OPPORTUNITY` — сказать «у вас устаревший дизайн»: его кто-то выбирал и, возможно, до сих пор работает там. `TECHNICAL_PROBLEMS` — назвать причину техническими словами |
| `HIGH_REVENUE_LOW_QUALITY` **запрещает упоминать выручку, трафик и рост**    | Это сторонние оценки StoreLeads, они часто неверны, и процитировать владельцу его же цифры читается как слежка. Оценок нет и в самом листе фактов — на лист попадает только число товаров                                  |
| QC судит **четыре пункта из семи**; длину и повторяемость приносит код       | Счётчик слов и коэффициент схожести — это числа. Отдать число на суд модели значит пригласить её быть дипломатичной. У 5-04 хватает по-настоящему субъективного: факты, персонализация, соответствие категории, тон        |
| Рецензент видит **тот же лист фактов**, что и автор, и больше ничего         | Именно это делает проверку фактов возможной. Модель, которую просят сверить письмо с магазином, которого она не видит, может только гадать — и будет гадать PASS                                                           |
| Любой единичный FAIL валит письмо                                            | QC, который взвешивает пункты друг против друга, пропустит выдуманное утверждение из-за хорошего тона. Выдуманное утверждение — единственное, что не должно уйти никогда                                                   |
| Непроверенный пункт помечается `NOT_CHECKED`, а не `PASS`                    | Молчание не должно читаться как одобрение. Но и валить письмо за то, что детектор 5-07 ещё не написан, нельзя                                                                                                              |
| Рецензент, не сумевший ответить, **валит черновик**, а не пропускает         | Отказ проверки — не то же самое, что успешная проверка. Причина при этом честно называет QC, а не черновик                                                                                                                 |

### Решения по 5-06 и 5-07 (реализовано 2026-09-08)

| Решение                                                                              | Причина                                                                                                                                                                                                   |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Два вложенных цикла**: внутренний на программных проверках, внешний на вердикте QC | Внутренний бесплатный, поэтому письмо на 300 слов переписывается без единого платного мнения о нём. Внешний стоит вызова, поэтому видит только черновики, уже прошедшие дешёвые проверки                  |
| Черновик, провалившийся на проверках 5-05, **до QC не доходит вообще**               | Платить за мнение о письме, про которое уже известно, что оно не той длины, незачем                                                                                                                       |
| Оба цикла ограничены; `QC_FAILED` — законный исход                                   | Альтернатива — крутить, пока что-нибудь не пройдёт: так пайплайн тратит день и сотню долларов, уговаривая себя отправить письмо, которое отправлять не следовало                                          |
| Шинглы + Жаккар, а не TF-IDF (план допускал оба)                                     | TF-IDF меряет, об одном ли тексты — а наши письма всегда об одном: сломанные корзины и медленные телефоны. Шинглы меряют, из одних ли они предложений, а это и есть вопрос                                |
| Окно — 4 слова                                                                       | Достаточно короткое, чтобы поймать переписанное предложение, и достаточно длинное, чтобы два письма с обычными оборотами («на telefonie», «на стронie продукту») не выглядели одинаковыми                 |
| Порог 0.4 помечен как **некалиброванный**                                            | Это отправная точка, а не измерение. Где на самом деле проходит граница — ровно то, что должна выяснить ручная проверка 5-09. Живёт одной именованной константой, чтобы тот проход менял её в одном месте |
| Отклонённые черновики тоже участвуют в сравнении                                     | Письмо, повторяющее забракованное, ничем не лучше повторяющего отправленное. Проблема в общем каркасе, а не в судьбе более раннего черновика                                                              |
| Ближайшее письмо называется по id                                                    | Чтобы человек мог положить два письма рядом и увидеть, что именно повторилось                                                                                                                             |

### Шаг `email_generation` подключён

Идёт последним и зависит почти от всего: аудит даёт факты, аналитик — их смысл, классификатор —
причину, поиск контактов — адресата. Магазин без классификации пропускается, а не получает письмо
вслепую: письмо без причины — это и есть та самая массовая рассылка.

Отклонённый черновик **сохраняется, но шаг рапортует SKIPPED**: отчёт по прогону, засчитавший его
как успех, спрятал бы отказ. `isSatisfied` считает магазин готовым при `READY`, `APPROVED` или
`SKIPPED` — забракованный черновик не готов, следующий прогон попробует снова.

### Решения по 6-09 (реализовано 2026-09-08)

Копирование в буфер уже было в карточке письма; добавлен экспорт одобренных.

| Решение                                                                         | Причина                                                                                                                                                                                                                                |
| ------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Route handler `GET /api/emails/export`, а не server action                      | Экспорт отдаёт файл. Action возвращает данные в React, и превращать их в скачивание — это собирать blob в браузере. GET с `Content-Disposition` браузер умеет сам, и тот же URL работает из терминала                                  |
| Экспортируются **только `APPROVED`**                                            | Это передача работы человеку, который отправит письма руками. Черновик, на который никто не смотрел, в файле оказаться не должен                                                                                                       |
| Ячейка, начинающаяся с `=`, `+`, `-`, `@`, таба или CR, экранируется апострофом | Excel и Sheets исполняют такую как формулу. Все строки здесь пришли с чужих сайтов, а файл открывают на своей машине. Побочно `-5` тоже экранируется: не уметь вычесть в таблице дешевле, чем исполнить строку со скрапленной страницы |
| Кавычки ставятся **всегда**, а не по необходимости                              | В теле письма запятые и переводы строк есть по определению. Решать для каждого значения — это как CSV-писалка получает свой первый баг                                                                                                 |
| Файл начинается с UTF-8 BOM                                                     | Без него Excel читает файл в локальной кодировке, и каждый `ł` превращается в мусор ровно там, где текст должен быть точным — его сейчас вставят в настоящее письмо                                                                    |
| Логика CSV лежит в `lib/csvExport.ts` **без импортов Next**                     | Тем же приёмом, что `runCommand.ts`: корневой набор тестов её прогоняет                                                                                                                                                                |

Проверено на живых данных: два одобренных письма, файл разбирается стандартным `csv`-парсером,
переводы строк в теле уцелели, польские символы целы.

**Найдено смоук-тестом на живых данных**: `node:sqlite` возвращает строки с null-прототипом, и React
отказывается передавать такую в клиентский компонент («Only plain objects…»). Карточка письма

| Решение                                                                     | Причина                                                                                                                                                                                                                                                             |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 7-02: один сквозной тест на фикстурах вместо набора                         | У каждого шага свой тест; этот нужен для того, чего те не видят, — что шаги стыкуются. Данные между ними ходят через БД, и ломается именно этот шов: аналитик пишет форму, которую писатель писем больше не читает. Юнит-тесты такое пропускают, живой прогон — нет |
| Сквозной тест поднимает локальный фикстур-сервер и подставной клиент модели | Проверяется наша проводка, а не сеть. Ошибиться мы можем только в ней                                                                                                                                                                                               |
| Аудит гоняется **один раз**, утверждения объединены                         | Один прогон аудита — 21 секунда. Три теста, каждый со своим прогоном, добавили бы минуту к каждому `npm test`                                                                                                                                                       |
| 7-04: отчёт — чистая функция над строками `step_logs`, печать отдельно      | Тестируется без прогона, и те же числа потом отдаст дашборд, не проходя через stdout                                                                                                                                                                                |
| Читатель токенов знает три разные формы `meta_json`                         | Аналитик пишет массив по агентам, поиск контактов — свои итоги, письма — писателя и рецензента раздельно. Навязывать трём разным работам одну схему хуже, чем знать три. Незнакомая форма даёт ноль: итог — это пол, а не догадка                                   |
| Считается только **последняя попытка** шага                                 | Ретрай, который в итоге прошёл, — это успех. Считать обе — превратить лестницу ретраев в процент отказов                                                                                                                                                            |
| 7-07: `VACUUM INTO`, а не копирование файла                                 | SQLite в WAL держит свежие записи в боковом файле. Копия `database.sqlite` во время прогона — это файл без новых строк или порванный. А бэкап нужен именно тогда, когда что-то идёт                                                                                 |
| Скриншоты копируются только по флагу                                        | БД — единственное место, где существуют находки, контакты и письма; всё остальное пересчитывается прогоном. Скриншоты большие и воспроизводимые                                                                                                                     |

Найдено при первом же запуске: метка времени бэкапа выходила как `2026-09-08T1` и не совпадала с
тем, что ищет очистка старых — та молча не удаляла бы ничего никогда.

## Cloudflare и вежливость к магазинам (2026-09-02)

Проблема: `--force` по батчу из десяти магазинов получил 429 на всех, включая те пять, что
отработали пятью минутами раньше. Разбор — на замерах, не на догадках.

| Замер                                                                                                       | Вывод                                                                                                                   |
| ----------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| **38 запросов на магазин за проход**: аудит 30, поиск контактов 8. `/cart` и `/cart.js` — по 7 раз          | Корзину резать нельзя: `/cart.js` перечитывается после каждой мутации, это единственный источник правды о её содержимом |
| **Кулдауна не было вообще**: BLOCKED писался в `audits`, но следующий прогон шёл на тот же домен немедленно | Это и есть причина потери доступа: на отказ мы отвечали новым запросом                                                  |
| **`robots.txt` читался как SEO-находка, но не исполнялся**                                                  | Ни `Disallow`, ни `Crawl-delay`                                                                                         |
| **Блокировка держится около часа**: три магазина, заблокированные в 11:37, ответили 200 в 12:20             | Кулдаун стартует с часа и удваивается, а не выставляется на сутки                                                       |

### Что сделано

| Решение                                                                                                    | Причина                                                                                                                                                                                                                      |
| ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Таблица `domain_cooldowns`: отказ → час, дальше удвоение до суток                                          | На отказ отвечаем молчанием, а не новым запросом. `Retry-After` побеждает, если сайт его прислал; более короткий `Retry-After` наш бэкофф не укорачивает                                                                     |
| Кулдаун проверяют **оба** шага, и `--force` его не обходит                                                 | Именно `--force` нанёс ущерб. Тест проверяет, что остывающий магазин не получает вообще ни одного запроса                                                                                                                    |
| Успешный заход снимает кулдаун                                                                             | Иначе один плохой день закрыл бы магазин навсегда                                                                                                                                                                            |
| Мёртвый хост кулдауна не получает                                                                          | Отказ и авария — разное; бэкофф на аварии спрятал бы её                                                                                                                                                                      |
| **Поиск контактов представляется честно** (`StoreLeadBot/0.1 (+CRAWLER_CONTACT)`) и исполняет `robots.txt` | Ему достоверность не нужна — нужен только текст страниц. Проверено вживую: с ботским UA магазины отдали всё как обычно                                                                                                       |
| **Аудит остаётся браузером** и `robots.txt` не исполняет                                                   | Он проверяет то, что видит покупатель. Магазин, отдающий боту другую страницу, сделал бы находки враньём. Вдобавок дефолтный `robots.txt` Shopify запрещает `/cart` и `/checkout` — проверки 2-13 и 2-14 стали бы невозможны |
| Команда `pipeline cooldowns [list\|clear <domain>]`                                                        | Видно, кого мы сейчас не трогаем и почему                                                                                                                                                                                    |

Маскировку не наращивали: ни stealth-плагинов, ни ротации прокси, ни подмены отпечатка. Замеры
показали, что дело в повторении, а не в том, что нас раскусили по отпечатку.

Задача **7-06 закрыта** этим разделом.
